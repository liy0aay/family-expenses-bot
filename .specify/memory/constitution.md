# Конституция проекта family-expenses-bot

Принципы обязательны на этапах plan/tasks/implement: каждое решение сверяется с ними (Constitution Gate). Операциональные правила для кодинг-агентов — AGENTS.md в корне репо.

## Core Principles

### I. Права решает домен
Проверка доступа и валидация — только в internal/service. В боте user_id владельца передаётся строго через context.Context (UserScope); в веб-панели главы семьи действует FamilyHeadScope: все траты семьи, user_id как опциональный фильтр из query. Хендлеры и LLM не принимают решений о доступе.

### II. Деньги — целые
Суммы в БД, домене и ответах REST — в копейках (amount_minor, int64). float64 для денег запрещён. На входах — REST-запросы (десятичная строка amount_rub) и тулы LLM (number) — сумма приходит в рублях и конвертируется единственной функцией RublesToKopecks.

### III. LLM не доверяем в детерминированных задачах
LLM извлекает намерения и параметры из естественного языка. Арифметика, права и валидация данных — детерминированный Go-код.

### IV. Категории: slug внутри, русский снаружи
В БД, домене и схемах тулов — slug (food, transport, housing, entertainment, health, shopping, other). В ответах бота и веб-панели — русские названия из ТЗ (еда, транспорт, жильё, развлечения, здоровье, покупки, другое). Вход нормализует NormalizeCategory (включая е -> ё). Пользователь никогда не видит slug'ов.

### V. Время — через Clock
time.Now() запрещён в internal/agent и internal/service. Инжектируемый Clock обеспечивает воспроизводимость evals на относительных датах («вчера», «в этом месяце»).

### VI. Один запуск
Вся система с зависимостями поднимается командой docker compose up. Пустой TELEGRAM_BOT_TOKEN — не ошибка: сервис стартует в режиме Web-API only.

### VII. Прагматичный стек, решения записаны
Проверенные инструменты без лишних зависимостей; новая зависимость — только с обоснованием в ADR. Нетривиальное решение — короткий ADR в docs/decisions.md в том же коммите.

## Governance

- Конституция главнее остальных практик; конфликт решается в её пользу.
- Изменение принципа — отдельный коммит: bump версии + правка затронутых артефактов (spec/plan/AGENTS.md).
- Ревью каждого диффа проверяет соответствие принципам; сложность требует обоснования.
